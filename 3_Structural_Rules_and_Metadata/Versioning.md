# Version Numbering (vMAJOR.MINOR.PATCH)

A version number shows what has changed in a document, tool, or dataset over time.

**Format:**
```
v[MAJOR].[MINOR].[PATCH]
Example: v2.3.1
```

---

## 🔎 How to Read the Version

### 1. **MAJOR (vX.00.00) – Big Changes**
- Large structural updates
- New calculations or logic added/removed
- Significant redesign or purpose change

**Example:**
- v1.0.0 → v2.0.0  
  → Major redesign or new methodology introduced

---

### 2. **MINOR (v1.X.00) – Moderate Changes**
- Small structural adjustments
- Minor calculation updates
- New fields, columns, or features added

**Example:**
- v2.1.0 → v2.2.0  
  → A new metric or minor logic adjustment added

---

### 3. **PATCH (v1.1.X) – Small Fixes**
- Text edits
- Formatting changes (font, colour)
- Corrections with no impact on calculations

**Example:**
- v2.2.1 → v2.2.2  
  → Typo fix or colour update only

---

## ✅ How to Choose the Correct Version

When making a change, ask:

| Question | Version to Update |
|----------|------------------|
| Does this change how results are calculated or major structure? | **MAJOR** |
| Does this add or adjust (but not overhaul) logic or structure? | **MINOR** |
| Is it only wording, formatting, or cosmetic? | **PATCH** |

---

## 📊 Example Progression

```
v1.0.0  Initial version  
v1.1.0  Added new field  
v1.1.1  Fixed typo  
v1.2.0  Updated calculation logic  
v2.0.0  Major redesign  
```
